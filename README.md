# 东方财富 财报 / 研报 批量下载器

一条命令，把某只 A 股在指定时间段内的**券商研报**和**定期报告（财报）**PDF 全部抓下来，自动按规范命名、生成清单、校验完整性、打包 zip。

```
eastmoney-downloader/
├── eastmoney_downloader.py     ← 程序本体（单文件，约 900 行）
├── run.sh                      ← macOS / Linux 启动脚本
├── run.bat                     ← Windows 启动脚本
├── requirements.txt            ← 可选增强依赖（不装也能用）
└── README.md
```

---

## 一、为什么叫「可迁移」

| 特性 | 说明 |
|---|---|
| **零依赖** | 只用 Python 标准库，`pip install` 一个包都不需要 |
| **单文件** | 整个程序就是一个 `.py`，拷走即可，没有包/模块引用 |
| **跨平台** | Windows / macOS / Linux 同一份代码，无平台分支 |
| **无绝对路径** | 不读任何固定位置的文件、不写系统目录，输出落在当前目录 |
| **无外部命令依赖** | 自实现了 PDF 元数据解析（不再依赖 macOS 的 `mdls`）；`curl` 仅作极端情况兜底，缺失会自动跳过 |
| **断点续传** | 中断后重跑同一条命令即可接着下，已下载的不重复 |
| **幂等** | 重复执行不会产生 `_2` 副本，文件数恒定 |

只要机器上有 **Python 3.7+**，把整个文件夹拷过去就能跑。

## 二、快速开始

### 1. 检查环境（可选，但建议先跑一次）

```bash
python eastmoney_downloader.py --doctor
```

会自检 Python 版本、控制台编码、以及 5 个东财接口的连通性，形如：

```
Python      : 3.9.6 (/usr/bin/python3)
平台        : Darwin 25.4.0
curl        : /usr/bin/curl
pypdf       : 未安装（可选，不影响功能；核心解析已内置）
--------------------------------------------------------
  研报列表接口       ✓  0.29s
  公告列表接口       ✓  0.25s
  F10 板块接口     ✓  0.47s
  PDF 下载节点     ✓  1.36s
  名称查询接口       ✓  0.24s
  简称/行业        ✓  贵州茅台 / 白酒
```

### 2. 下载

```bash
# 贵州茅台 2026 全年：研报 + 财报，并打包
python eastmoney_downloader.py --code 600519 --period 2026 --zip

# 也支持直接写公司名
python eastmoney_downloader.py --name 五粮液 --period 2026H1

# 只要研报
python eastmoney_downloader.py --code 600519 --period 2026 --types report

# 先看清单再决定下不下
python eastmoney_downloader.py --code 600519 --period 2026 --list-only
```

Windows 下把 `python` 换成 `py` 或 `python3`，也可以直接双击 `run.bat`。

## 三、参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--code` | 6 位股票代码，如 `600519` | 与 `--name` 二选一 |
| `--name` | 公司名，如 `茅台`，自动解析成代码 | — |
| `--period` | `2026` / `2026H1` / `2026H2` / `2026Q1`~`Q4` / `2026-03`（整月）/ `2026-01-01~2026-06-30` | 当年 |
| `--year` | 等价于 `--period 2026` | — |
| `--begin` / `--end` | 直接指定起止日期 `YYYY-MM-DD` | — |
| `--types` | `report`=研报、`ann`=财报公告，逗号分隔 | `report,ann` |
| `--ann-filter` | `periodic` 只留定期报告 / `all` 全部公告 / `keyword` 关键词筛选 | `periodic` |
| `--ann-keyword` | 配合 `--ann-filter keyword` | — |
| `--out` | 输出目录 | `./<公司简称><代码>_<时间>_财报研报` |
| `--list-only` | 只抓清单不下载 | 关 |
| `--zip` | 完成后打包 | 关 |
| `--sleep` | 每次下载间隔秒数，**勿低于 0.5** | `0.6` |
| `--doctor` | 环境与接口自检 | — |
| `--version` | 版本号 | — |

命名模板相关（正常不需要改）：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--name-spec` | 研报命名模板 | `{date}_{ind}_{company}{code}_{org}_{author}` |
| `--name-spec-ann` | 财报命名模板 | `{date}_{ind}_{company}{code}_{title}` |
| `--date-from` | `pdf` 用研报自身日期 / `api` 用东财发布日 | `pdf` |
| `--author-sep` | 多作者连接符 | `_` |

可用占位符：`{date}` `{apdate}` `{ind}` `{company}` `{code}` `{org}` `{author}` `{title}`

## 四、输出结构

```
五粮液000858_2026H1_财报研报/
├── 财报/
│   ├── 260417_白酒_五粮液000858_2025年年度报告.pdf
│   └── ...
├── 研报/
│   ├── 260307_白酒_五粮液000858_国信证券_张向伟_张未艾.pdf
│   └── ...
├── 清单.csv          ← 可导入 Excel（含来源链接）
├── 清单.md           ← 带可点击的相对路径
├── 清单.html         ← 打开即看的索引页
├── manifest.json     ← 结构化数据，供二次处理
```

同名 `.zip` 生成在输出目录的**上一级**。zip 强制写入 UTF-8 文件名标志位，因此在 Windows 上解压也不会乱码。

## 五、命名规范

```
研报：<YYMMDD>_<行业>_<公司简称+代码>_<机构>_<研究员>.pdf
      260918_白酒_贵州茅台600519_诚通证券_陈文倩.pdf

财报：<YYMMDD>_<行业>_<公司简称+代码>_<报告名>.pdf
      260417_白酒_贵州茅台600519_2025年年度报告.pdf
```

- **行业**：取东财申万行业，自动去掉罗马数字后缀（`白酒Ⅱ` → `白酒`）
- **公司字段**：简称与 6 位代码**直接拼接**，不加括号
- **多作者**：下划线连接（`朱会振_舒尚立`）
- **日期口径**（两者不同，这是有意为之）：

| | 日期含义 | 来源 |
|---|---|---|
| 研报 | 研报**自身标注日期** | PDF 元数据标题 → 封面正文 → PDF 生成日期 |
| 财报 | **披露日期**（公告日） | 公告 `notice_date` |

> 东财的 `publishDate` 通常比研报自身日期**晚 0–4 天**，所以不能直接用它命名。财报 PDF 封面是版式生成的图形，**提取不到文本日期**，只能用公告日。

## 六、日期是怎么识别出来的（零依赖实现）

研报命名依赖「研报自身日期」，而东财接口**没有**这个字段（只有 `publishDate`），所以必须从 PDF 里取。程序内置三级回退：

| 级别 | 来源 | 依赖 | 覆盖率（47 篇实测） |
|---|---|---|---|
| 1 | PDF 元数据 `/Title` 或 XMP `dc:title`，形如 `机构-公司(代码)标题-260918.pdf` | 无 | 35/47 |
| 2 | PDF 自身的 `/CreationDate` / `/ModDate` | 无 | +12/47 |
| 3 | 首页正文文本（`pypdf` 或 `pdftotext`） | 可选 | 冗余兜底 |
| 末 | 东财发布日 | 无 | 保底 |

**第 1、2 级加起来就是 47/47，零误差、零依赖。** 第 3 级只是为了多一层保险。

第 2 级有个防误用设计：`/CreationDate` 偶尔是「文件生成时间」而非报告日期，因此只接受落在 `[publishDate - 12 天, publishDate]` 区间内的取值，出界就弃用、回退到发布日。

运行时会在结尾打印各来源的命中数：

```
研报日期来源：元数据标题 35 / 封面正文 0 / PDF生成日 12 / 回退发布日 0
```

## 七、常见问题

**Q：某个文件一直 `✗`，提示 `非 PDF 内容 len=987`？**

说明 `pdf.dfcfw.com` 这次没返回 PDF，而是吐了一个几百字节的错误页（CDN 缓存或源站抽风），**不是你参数错了**。程序已经处理：

- 每轮重试会**换一个地址形态**：裸链 → 带缓存击穿参数的链接 → 公告详情接口里给出的权威地址（最多 5 轮，间隔 2/4/6/8 秒并带随机抖动）
- 全部失败则该条目记为失败，**不会**写入残缺文件

跑完如果还有失败，结尾会打一段醒目告警并列出具体是哪些报告：

```
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
警告：有 1/17 个文件没下下来（重试后仍失败，通常是服务端临时故障）。
   - 2026-09-12  五粮液:2026年半年度报告(英文版)
   直接重跑同一条命令即可补齐：已成功的会跳过，不会重复下载。
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
```

**直接重跑同一条命令**即可，已成功的会跳过。若想脚本化判断成败，看**退出码**：全部成功为 `0`，有文件未下下来为 `2`。

**Q：接口报 `Remote end closed connection without response`？**
东财行情类接口会拒绝 Python 的 TLS 指纹，且 `push2*` 域名解析到 IPv6 时会空回复。程序已内置：首选 `datacenter-web` 的 F10 板块接口取「简称+行业」（实测最稳），失败再回退到 `push2*` 多域名轮询，并自动用 `curl` 兜底。偶发失败会自动重试。

**Q：下载到一半断了怎么办？**
重跑同一条命令。缓存每下载一份就落盘一次，已完成的会跳过。**不要**手动删 `.downloaded.json`（虽然删了也不会出错，只是会重新下载一遍）。

**Q：为什么有的研报没下到？**
东财只收录公开发布的研报。假如某券商未上传，接口里就没有这条记录，程序无法凭空获取。

**Q：`--sleep` 能调小吗？**
不建议低于 0.5 秒，容易被限流。默认 0.6 秒。

**Q：支持港股 / 美股吗？**
不支持，当前只覆盖 A 股。港股美股走的是另一套接口和 PDF 地址前缀。

**Q：需要装 `pypdf` 吗？**
不需要。它是纯冗余兜底，装了也不会改变结果（已交叉验证 47 篇文件名完全一致）。
